## 1. 目标

P1 里 agy 的 `session/request_permission` 全部由主进程按 `autoApprove` 自动回答（`cli` 一律拒绝、问题一律取消）。P2 改成：**需要人决定的请求在聊天界面里显示成卡片，用户点按钮回答**。

| 账号 `autoApprove` | 命令 / 项目外编辑等 | 项目内编辑 | 读取 / 搜索 / 抓取 / 思考 | agy 的提问（`interaction_*`） |
|---|---|---|---|---|
| `full` | 自动允许 | 自动允许 | 自动允许 | **问用户** |
| `edits` | **问用户** | 自动允许（沿用 P1 的路径检查 `insideProject`） | 自动允许 | **问用户** |
| `cli` | **问用户** | **问用户** | **问用户**（agy 一般不会对这些发请求，发了就问） | **问用户** |

“自动允许”的逻辑和 P1 完全一样（`agyPermission` 现有规则），只是把 P1 里“拒绝 / 取消”的分支改成“问用户”。

## 2. 数据结构（`src/shared/types.ts`）

新增 `AgentEvent` 两个成员：

```ts
| {
    t: 'permission'
    /** Unique per request; the renderer replies with it. */
    requestId: string
    /** approval: allow/deny a tool call. question: agy asks the user to pick an answer. */
    kind: 'approval' | 'question'
    /** Tool card this request belongs to (`agy:<toolCallId>`), when there is one. */
    activityId?: string
    /** approval: tool name; question: the question text (toolCall.title). */
    title: string
    /** approval: command line / file paths, already capped (capText 4KB). */
    detail?: string
    options: { id: string; label: string; role: 'allow_once' | 'allow_always' | 'reject_once' | 'reject_always' | 'answer'; warning?: string }[]
    /** Epoch ms after which the main process answers by itself. */
    expiresAt: number
  }
| { t: 'permission_resolved'; requestId: string; outcome: 'selected' | 'cancelled' | 'timeout'; optionId?: string; label?: string; by: 'user' | 'auto' }
```

- `options` 由主进程从 agy 的 `options` 生成：approval 按 `kind` 映射 role（agy 没给的不生成）；question 每个选项 role 都是 `'answer'`，label 用 `option.name`（空则用 `optionId`），按 200 字符截断。
- `warning`：`allow_always` 选项的 `_meta['agy.security.warning']` 里的 `message`（没有则用 `title`），截断到 512 字符。
- 渲染端额外总是显示一个「取消」按钮（不属于 options），回复 `cancelled`。

新增 IPC（`IPC` 常量里加，preload 的 `chat` 下暴露）：

| 名称 | 方向 | 参数 / 返回 |
|---|---|---|
| `chat:permissionReply` | renderer → main（invoke） | `(requestId: string, optionId: string \| null)`，`null` = 取消；返回 `boolean`（请求已不存在时返回 `false`，渲染端据此把卡片标成已失效） |
| `chat:pendingPermissions` | renderer → main（invoke） | 返回当前所有未决请求 `{ threadId, turnId, stepId, event }[]`（`event` 就是上面的 `permission` 事件），用于窗口刷新后恢复卡片 |

## 3. 主进程

### 3.1 新模块 `src/main/acp/permissions.ts`
一个进程内的未决请求登记表（单例）：

- `register({ threadId?, turnId?, stepId?, event, resolve })`：保存，并开一个超时定时器。
- `reply(requestId, optionId | null, by)`：校验 optionId 必须是该请求 options 里的 id（否则返回 `false`，不改变状态）；调用 `resolve`，清定时器，删除登记，返回 `true`。
- `cancelAll(predicate, outcome)`：批量取消（停止本轮、进程退出、应用退出时用）。
- `pending()`：列出未决请求。
- 超时：默认 **5 分钟**（常量，测试里可注入更短的值）。到点后：approval 回 `reject_once`（没有就 `cancelled`），question 回 `cancelled`；`by: 'auto'`，outcome `timeout`。
- 每次结束（无论用户 / 超时 / 取消）都要通过 emit 发一个 `permission_resolved`。

### 3.2 让权限回答变成异步
- `pool.ts` 的 `Listener.permission` 返回类型改成 `PermissionReply | Promise<PermissionReply>`；`AcpConnection.permission` 和 `onRequest` 同步透传 Promise（`jsonrpc.ts` 的 `respond` 已经支持 Promise，不用改）。
- `agySession.ts`：`agyPermission` 拆成两步：
  1. `autoDecision(request, level, cwd)` → `'allow' | 'ask'`（纯函数，沿用 P1 规则；问题一律 `'ask'`）。
  2. `'allow'` 时按 P1 的方式选 `allow_once` 立即回复（保留 onLog）。`'ask'` 时：生成 `permission` 事件 → `emit` → 在登记表 `register` → 返回一个 Promise，等用户 / 超时 / 取消。
- 发 `permission` 事件之前，确保对应工具卡片已经存在：如果 `toolCall.toolCallId` 还没有出现在本轮的 `tools` map 里，先用 `toolCall` 本身走一遍 P1 的 `tool_call` 映射，emit 卡片（状态 running），`activityId` 指向它。问题（`interaction_*`）不建工具卡片，`activityId` 留空。
- `stopped()` 为 true 或本轮已结束（`!prompting`）时收到的请求：直接回 `cancelled`，不弹卡片（P1 已有逻辑，保留）。
- 删除 P1 里 `main.acpInteraction` 和 `cli` 模式下的 `main.acpPermissionDenied` notice（现在改为弹卡片）；**超时**时改发一条 notice（新文案 `main.acpPermissionTimeout`：“{name} 等待确认超过 5 分钟，已自动拒绝”/问题：“已自动跳过”）。

### 3.3 停止与清理
- `runAgyAcp` 的 `kill()`：在发 `session/cancel` **之前**，先把本轮所有未决请求 `cancelAll(..., 'cancelled')`（agy 在等权限回答时不会处理 cancel）。
- 本轮结束的 `cleanup()`：取消本轮残留的未决请求。
- 进程退出 / `pool.retire`：取消该连接上的所有未决请求。
- `index.ts` 的 `before-quit`：`cancelAll`。

### 3.4 把事件和对话关联起来
`permission` 事件需要知道属于哪个 thread / turn / step，渲染端才能放到对应消息里。现有 orchestrator 的 `emit` 已经会给 AgentEvent 包上 `{ kind: 'agent', threadId, turnId, stepId }`，所以：
- `RunSpec` 增加可选字段 `ref?: { threadId: string; turnId: string; stepId: string }`，orchestrator 调 `runAgent` 时传入（`src/main/orchestrator.ts` 里调用 `runAgent` 的那一处，字段名看现有 `ids`）；`usage.ts` 里的探测调用不传。
- `register` 时带上 `ref`，`pending()` 返回它。
- `ipc.ts`：注册两个 handler；`chat:permissionReply` 调 `permissions.reply(id, optionId, 'user')`。

### 3.5 用户不在窗口前时提醒
请求弹出时，如果主窗口不是聚焦状态：调用一次 `app.dock?.bounce('informational')`。不做系统通知（以后再说）。

## 4. 渲染端

### 4.1 状态（`src/renderer/src/state/chat.ts`）
- `AssistantMessage` 增加 `permissions?: PendingPermission[]`，`PendingPermission = Extract<AgentEvent,{t:'permission'}> & { resolved?: { outcome; optionId?; label?; by } }`。
- 处理 `permission`：追加（同 requestId 去重）。处理 `permission_resolved`：给对应项写 `resolved`。
- 启动 / 窗口刷新时（和现有 `chat.active()` 恢复运行中轮次的地方放在一起）调用 `chat.pendingPermissions()`，把结果按 `stepId` 合并进对应消息。
- 从磁盘恢复的历史消息里如果有没 `resolved` 的项，而该 step 已经不在运行中：标成 `resolved: { outcome: 'cancelled', by: 'auto' }`，不显示按钮。

### 4.2 卡片组件（`src/renderer/src/components/Process.tsx` 或新文件 `PermissionCard.tsx`）
- 位置：有 `activityId` 的，放在对应活动行的下方；没有的（问题），放在消息正文上方、活动栏下方。
- **approval 卡片**：标题（工具名 + `detail` 第一行），可展开看完整 `detail`（等宽字体）；按钮按 role 显示：「允许」（allow_once，主按钮）、「本会话都允许」（allow_always，有 warning 时按钮旁显示 ⚠️ 和 warning 文字）、「拒绝」（reject_once）、「取消」。
- **question 卡片**：问题文字（Markdown 渲染用现有 `Markdown` 组件，但禁用链接自动打开以外的交互即可）+ 每个选项一个按钮 + 「跳过」（= 取消）。
- 显示剩余时间（`expiresAt` 倒计时，分:秒，最后 30 秒变成警告色）。用现有 `useNow` 之类的工具，别每个卡片自己开 setInterval 风暴（一个卡片一个 1s interval 可以接受）。
- 点击后：立刻禁用所有按钮（防重复点），调用 `chat.permissionReply`；返回 `false` 时显示“请求已失效”。
- 已解决的卡片折叠成一行：“已允许 / 已拒绝 / 已回答：<label> / 已取消 / 超时自动拒绝”，approval 的 by=auto 显示“（自动）”。
- 键盘可用：按钮是真 `<button>`，有 `aria-label`；卡片出现时不要抢焦点（用户可能正在输入）。
- 样式跟随现有活动卡片（Tailwind 类名参照 `ActivityRow`），浅色/深色主题都要看得清。

### 4.3 其他界面
- 有未决请求的会话：侧边栏 / 消息头上现有的“运行中”指示旁边加一个小提示（例如 ⏳ 或文案「等待你确认」）。找现有显示运行状态的地方加，改动越小越好；找不到合适位置就只在消息内显示卡片，并在交付说明里写明。
- `ProfileConfigModal.tsx`：ACP 打开时的权限说明文案（`cfg.acpApprovalCli` / `Edits` / `Full`）改成新行为：`cli`“每个需要确认的操作都会在对话里询问你”、`edits`“项目内编辑自动允许，命令和项目外的改动会在对话里询问你”、`full`“工具请求自动允许；Gemini 提问时仍会询问你”。

### 4.4 i18n
新增文案 4 种语言（`en`、`ja`、`zh-CN`、`zh-TW`）全部补齐：按钮、已解决状态、倒计时、请求已失效、等待你确认、超时 notice、改写的 3 条设置说明。删除不再使用的 `main.acpInteraction`；`main.acpPermissionDenied` 如果不再使用也删除。

## 5. 测试（vitest）

1. `permissions.ts`：register → reply 正常；reply 不存在的 id / 非法 optionId 返回 false；超时后 approval 回 reject_once、question 回 cancelled、各发一次 `permission_resolved`；`cancelAll` 按条件取消；同一请求重复 reply 只生效一次。
2. `autoDecision` 决策表：第 1 节表格里 12 种组合全部覆盖（含项目外编辑、`interaction_`）。
3. `agySession` 集成（复用现有 `fakeAgy`）：
   - `cli` 模式收到 execute 权限请求 → emit `permission`（含正确 options、activityId 指向已存在的卡片）→ 模拟 `permissions.reply` 选 allow → 假 agy 收到 `{outcome:{outcome:'selected',optionId:'allow'}}`。
   - `full` 模式收到 `interaction_` 问题 → 弹卡片，选一个答案 → agy 收到该 optionId。
   - 等待回答期间 `kill()` → agy 先收到权限 `cancelled` 回复，**再**收到 `session/cancel`（断言顺序），卡片 resolved 为 cancelled。
   - 超时（fake timers）→ agy 收到 reject，emit notice。
   - 本轮结束后迟到的权限请求 → 直接 cancelled，不 emit `permission`。
4. 渲染端状态 reducer（如果 `chat.ts` 的事件处理是可单独测试的函数就测；不方便就跳过并在交付说明里说明）：`permission` 去重、`permission_resolved` 合并、历史恢复时未决项被标成 cancelled。
